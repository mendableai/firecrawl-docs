A lead lands from someone at Firecrawl. Before anyone replies, your agent needs
three things the web will not give you cleanly:

1. Is the company real, funded, and how big?
2. Who works there and at what level?
3. What have they shipped in the last month?

The first answer lives in a company database, the second in a contact database,
and only the third is really on the open web. Reaching either of the first two
normally means finding the vendor, signing up, getting a key, learning their
schema, and running it as its own service. Three answers, three integrations.

Exchange puts those providers behind the contract you already use: the same
[`/search`](/api-reference/endpoint/search) call, the same API key. By the end
of this page, triaging that lead is a single request.

<Note>
Searching the catalog adds no credits to a request. Credits are charged when a
capability is executed; a web query alongside it bills as an ordinary search.
</Note>

## How it works

A provider is a data source: Crunchbase for company and funding records, Apollo
for people, and so on. A capability is one thing that provider can do, such as
searching organizations or finding a person by title. Each capability publishes a
JSON Schema for its options, a schema for its response, and a price in credits,
so an agent can build a valid call and know the cost before it commits. The
[provider catalogue](https://www.firecrawl.dev/exchange) lists everything
currently available.

## Building the brief

<Steps>
  <Step title="Ask who can answer it">
    Your agent does not need to know Crunchbase or Apollo exist. Name the data it
    needs and set `sources` to `exchange`: matching capabilities come back
    alongside your web results, shaped like any other result. There is no separate
    catalog endpoint, and searching it adds no credits.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      query: "company funding and people by title",
      sources: ["exchange"],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "query": "company funding and people by title",
        "sources": ["exchange"],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "company funding and people by title",
        "sources": ["exchange"]
      }'
    ```
    </CodeGroup>

    Matches arrive under `data.providers`, ranked. The `description` tells you what
    the capability does and what it costs, `provider` and `capability` are the keys
    you call it with, and the `url` resolves to its full request and response
    contract as Markdown. A response looks like this, trimmed to the two
    capabilities this page goes on to use:

    ```json wrap
    {
      "providers": [
        {
          "url": "https://www.firecrawl.dev/exchange/providers/crunchbase/company-search",
          "title": "Crunchbase — Search organizations",
          "description": "Find companies with structured firmographic and funding filters. 5 credits per call. Fetch the url for the full request and response contract.",
          "provider": "crunchbase",
          "capability": "company-search",
          "creditsPerCall": 5
        },
        {
          "url": "https://www.firecrawl.dev/exchange/providers/apollo/people-search",
          "title": "Apollo — Search people",
          "description": "Find net-new prospects using title, seniority, location, and organization filters. 5 credits per call. Fetch the url for the full request and response contract.",
          "provider": "apollo",
          "capability": "people-search",
          "creditsPerCall": 5
        }
      ]
    }
    ```

    Ranking weights a capability name above a provider blurb that merely mentions
    the words. Matching is lexical, so name the data you want rather than the
    situation you are in: "company funding" and "people by title" rank well,
    "research this lead for me" does not.

    To see everything available rather than search it, browse the
    [provider catalogue](https://www.firecrawl.dev/exchange).
  </Step>

  <Step title="Narrow it down (optional)">
    When you already know the shape of the answer, say so. Use the object form of
    the source to scope discovery: `categories` limits it to a cohort, `providers`
    to named providers, and `capabilities` to specific `provider/capability`
    pairs. They compose, so a cohort plus a provider narrows further.

    Filters work with or without a query. Drop the query to browse everything in a
    cohort; add one to rank within it.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      sources: [
        {
          type: "exchange",
          categories: ["people", "finance"],
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "sources": [
            {
                "type": "exchange",
                "categories": ["people", "finance"],
            }
        ],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "enrich a contact",
        "sources": [
          { "type": "exchange", "categories": ["people", "finance"] }
        ]
      }'
    ```
    </CodeGroup>
  </Step>

  <Step title="Get the answer">
    Now fetch the company itself. Providers are called through
    [`/search`](/api-reference/endpoint/search): add an `exchange` array with the
    `provider`, the `capability`, and the `options` its input schema requires.

    `query` is optional. Omit it to call providers only, or include it to get web
    results and provider results back together in one request.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      exchange: [
        {
          provider: "crunchbase",
          capability: "company-search",
          options: { query: "Firecrawl", limit: 1 },
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "exchange": [
            {
                "provider": "crunchbase",
                "capability": "company-search",
                "options": {"query": "Firecrawl", "limit": 1},
            }
        ]
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "exchange": [
          {
            "provider": "crunchbase",
            "capability": "company-search",
            "options": { "query": "Firecrawl", "limit": 1 }
          }
        ]
      }'
    ```
    </CodeGroup>

    Provider results arrive under `data.exchange`, and each call is reported
    separately so one failure does not discard the rest:

    ```json wrap
    {
      "success": true,
      "data": {
        "exchange": [
          {
            "provider": "crunchbase",
            "capability": "company-search",
            "delivery": "direct",
            "creditsCost": 5,
            "data": {
              "organizations": [
                { "name": "Firecrawl", "permalink": "firecrawl", "founded_on": "2024-04-01" }
              ]
            }
          }
        ]
      },
      "creditsUsed": 5,
      "id": "0198f3c2-..."
    }
    ```

    A call that fails carries an `error` object with a `code`, a `message`, and
    `retryable` instead of `data`.
  </Step>
</Steps>

## The whole brief, one request

Each step so far answered one part. They compose: the `exchange` array takes up
to ten calls, and a `query` runs a web search alongside them.

So the brief we started with — what Firecrawl is, who works there, and what is
being written about it — is one request across three sources. The company from
Crunchbase, the people from Apollo, the coverage from the web. No extra
accounts, no second endpoint, nothing to reconcile afterwards.

const result = await firecrawl.search({
  query: "firecrawl",
  sources: ["news"],
  exchange: [
    {
      provider: "crunchbase",

      options: { query: "Firecrawl", limit: 1 },

});

## Pricing

Searching the catalog adds no credits. Running a capability costs the
`creditsPerCall` published in its contract, and you are charged only for calls
that succeed. Discovery results carry the price, so you can check before
calling.
