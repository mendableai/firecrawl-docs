Firecrawl Exchange takes your agent beyond the web. Plenty of the data an agent
needs is not on a page at all: it sits behind a specialist API you would
otherwise have to find, sign up for, get a key from, and wire up as its own
service. Exchange puts those providers behind the contract you already use.

You find providers and call them through [`/search`](/api-reference/endpoint/search), with the same API
key as every other Firecrawl request. Every provider publishes a contract
describing what it returns, what options it takes, and what a call costs.

<Note>
Searching the catalog adds no credits to a request. Credits are charged when a
capability is executed; a web query alongside it bills as an ordinary search.
</Note>

## How it works

A provider is a data source: Crunchbase for company and funding records, Apollo
for people, and so on. A capability is one thing that provider can do, such as
searching organizations or finding a person by title. Each capability publishes a JSON
Schema for its options, a schema for its response, and a price in credits. The
[provider catalogue](https://www.firecrawl.dev/exchange) lists everything
currently available.

## Using Exchange

<Steps>
  <Step title="Find a provider">
    Exchange has no separate catalog endpoint. Set `sources` to `exchange` on
    [`/search`](/api-reference/endpoint/search) and matching capabilities come back alongside your web
    results, shaped like any other result. Searching the catalog adds no credits.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      query: "company profile and people at that company",
      sources: ["exchange"],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "query": "company profile and people at that company",
        "sources": ["exchange"],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "company profile and people at that company",
        "sources": ["exchange"]
      }'
    ```
    </CodeGroup>

    Matches arrive under `data.providers`, best first. The `description` tells you
    what the capability does and what it costs, `provider` and `capability` are the
    keys you call it with, and the `url` resolves to its full request and response
    contract as Markdown:

    ```json wrap
    {
      "providers": [
        {
          "url": "https://www.firecrawl.dev/exchange/providers/crunchbase/company-search",
          "title": "Crunchbase — Search organizations",
          "description": "Find companies with structured firmographic and funding filters. 25 credits per call. Fetch the url for the full request and response contract.",
          "provider": "crunchbase",
          "capability": "company-search",
          "creditsPerCall": 25
        },
        {
          "url": "https://www.firecrawl.dev/exchange/providers/apollo/people-search",
          "title": "Apollo — Search people",
          "description": "Find net-new prospects using title, seniority, location, and organization filters. 25 credits per call. Fetch the url for the full request and response contract.",
          "provider": "apollo",
          "capability": "people-search",
          "creditsPerCall": 25
        }
      ]
    }
    ```

    Ranking weights a capability name above a provider blurb that merely mentions
    the words, so the closest match to your query comes first.

    To see the full list rather than search it, browse the
    [provider catalogue](https://www.firecrawl.dev/exchange).
  </Step>

  <Step title="Narrow the search (optional)">
    Use the object form of the source to scope discovery. `categories` limits it to
    a cohort, `providers` to named providers, and `capabilities` to specific
    `provider/capability` pairs. They compose, so a cohort plus a provider narrows
    further.

    Filters work with or without a query. Drop the query to browse everything in a
    cohort; add one to rank within it.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      sources: [
        {
          type: "exchange",
          categories: ["people", "finance"],
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "sources": [
            {
                "type": "exchange",
                "categories": ["people", "finance"],
            }
        ],
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "query": "enrich a contact",
        "sources": [
          { "type": "exchange", "categories": ["people", "finance"] }
        ]
      }'
    ```
    </CodeGroup>
  </Step>

  <Step title="Call the provider">
    Providers are called through [`/search`](/api-reference/endpoint/search). Add an `exchange` array with the
    `provider`, the `capability`, and the `options` its input schema requires.

    `query` is optional. Omit it to call providers only, or include it to get web
    results and provider results back together in one request.

    <CodeGroup>
    ```js Node
    const result = await firecrawl.search({
      exchange: [
        {
          provider: "crunchbase",
          capability: "company-search",
          options: { query: "Apple", limit: 1 },
        },
      ],
    });
    ```

    ```python Python
    result = firecrawl.search({
        "exchange": [
            {
                "provider": "crunchbase",
                "capability": "company-search",
                "options": {"query": "Apple", "limit": 1},
            }
        ]
    })
    ```

    ```bash cURL
    curl -X POST "https://api.firecrawl.dev/v2/search" \
      -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
      -H "Content-Type: application/json" \
      -d '{
        "exchange": [
          {
            "provider": "crunchbase",
            "capability": "company-search",
            "options": { "query": "Apple", "limit": 1 }
          }
        ]
      }'
    ```
    </CodeGroup>

    Provider results arrive under `data.exchange`, and each call is reported
    separately so one failure does not discard the rest:

    ```json wrap
    {
      "success": true,
      "data": {
        "exchange": [
          {
            "provider": "crunchbase",
            "capability": "company-search",
            "delivery": "direct",
            "creditsCost": 25,
            "data": {
              "organizations": [
                { "name": "Apple", "permalink": "apple", "founded_on": "1976-04-01" }
              ]
            }
          }
        ]
      },
      "creditsUsed": 25,
      "id": "0198f3c2-..."
    }
    ```

    A call that fails carries an `error` object with a `code`, a `message`, and
    `retryable` instead of `data`.
  </Step>
</Steps>

## Putting it together

Each step so far did one thing. The point of Exchange is that they compose: the
`exchange` array takes up to ten calls, and a `query` runs a web search
alongside them.

So a question like *"tell me about Apple, who runs AI there, and what is being
written about it"* is one request across three sources — the company from one
provider, the person from another, and news from the web.

<CodeGroup>
```js Node
const result = await firecrawl.search({
  query: "apple ai strategy",
  sources: ["news"],
  exchange: [
    {
      provider: "crunchbase",
      capability: "company-search",
      options: { query: "Apple", limit: 1 },
    },
    {
      provider: "apollo",
      capability: "people-search",
      options: {
        query: "Head of AI at Apple",
        filters: { titles: ["Head of AI", "VP Artificial Intelligence"] },
        limit: 5,
      },
    },
  ],
});

result.news; // coverage from the web
result.exchange; // the company and the people, in call order
```

```python Python
result = firecrawl.search({
    "query": "apple ai strategy",
    "sources": ["news"],
    "exchange": [
        {
            "provider": "crunchbase",
            "capability": "company-search",
            "options": {"query": "Apple", "limit": 1},
        },
        {
            "provider": "apollo",
            "capability": "people-search",
            "options": {
                "query": "Head of AI at Apple",
                "filters": {"titles": ["Head of AI", "VP Artificial Intelligence"]},
                "limit": 5,
            },
        },
    ],
})
```

```bash cURL
curl -X POST "https://api.firecrawl.dev/v2/search" \
  -H "Authorization: Bearer $FIRECRAWL_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "query": "apple ai strategy",
    "sources": ["news"],
    "exchange": [
      {
        "provider": "crunchbase",
        "capability": "company-search",
        "options": { "query": "Apple", "limit": 1 }
      },
      {
        "provider": "apollo",
        "capability": "people-search",
        "options": {
          "query": "Head of AI at Apple",
          "filters": { "titles": ["Head of AI", "VP Artificial Intelligence"] },
          "limit": 5
        }
      }
    ]
  }'
```
</CodeGroup>

Provider results arrive under `data.exchange` in the order they were sent, next
to `data.news` and the other web sources. Each call is reported separately, so
one provider failing does not discard the rest:

```json wrap
{
  "success": true,
  "data": {
    "news": [
      {
        "url": "https://www.example.com/apple-ai-roadmap",
        "title": "Apple details its on-device AI roadmap",
        "date": "2026-07-29"
      }
    ],
    "exchange": [
      {
        "provider": "crunchbase",
        "capability": "company-search",
        "delivery": "direct",
        "creditsCost": 25,
        "data": {
          "organizations": [
            { "name": "Apple", "permalink": "apple", "founded_on": "1976-04-01" }
          ]
        }
      },
      {
        "provider": "apollo",
        "capability": "people-search",
        "delivery": "direct",
        "creditsCost": 25,
        "data": {
          "people": [
            { "name": "Jane Doe", "title": "Head of AI", "organization": "Apple" }
          ]
        }
      }
    ]
  },
  "creditsUsed": 51,
  "id": "0198f3c2-..."
}
```

The web search bills as an ordinary search and each capability bills its own
`creditsPerCall`, so the cost of the whole request is the sum of its parts.

## Pricing

Searching the catalog adds no credits. Running a capability costs the
`creditsPerCall` published in its contract, and you are charged only for calls
that succeed. Discovery results carry the price, so you can check before
calling.

## List your data on Exchange

If you have an API you want agents to reach, you can publish it as a provider.
Upload an OpenAPI specification and Firecrawl derives your capabilities from it,
then walks you through pricing, categorisation, and ownership verification.
Every listing is reviewed before it becomes public.
